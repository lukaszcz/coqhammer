# MoreDep.v -- a known translation defect, not a missing feature.  Five goals
#   (present_balance1, present_balance2, present_ins, present_insert_Red,
#   present_insert_Black) reach a match whose scrutinee is a binder of type
#   `insResult Red n`, where insResult is a type-level Equations function with
#   `insResult Red n := rtree n`.  That type is convertible to an application of
#   the matched inductive but is not syntactically one, and the case translation
#   reads the actual index arguments off the scrutinee's declared type with
#   `flatten_app`, discarding the head without comparing it to the matched
#   inductive.  So insResult's own arguments are taken for rtree's indices --
#   two arguments, the first of them `Red : color`, for a family declaring one
#   nat index -- and the lockstep walk over (actual, constructor, formal)
#   indices reports "constructor result indices do not align with the case
#   predicate (1 actual, 0 constructor, 0 formal arguments remain)".
#   The scrutinee type must be head-normalized to an application of the matched
#   inductive, and the head must be checked, before any index guard is emitted.
#   Unrelated to the indexed-family/fording frontier: rtree's own indices align
#   fine.  Also unrelated to the primitive-projection handling fixed in "Expand
#   primitive projections before FOL encoding", which is what cleared the other
#   MoreDep failures.  Remove this exclusion once the defect is fixed.
#
# general_recursion.v -- the deliberately non-terminating `nonterm` example,

#   body drives coq_transl into a super-linear blow-up (feature extraction
#   completes; the cost is in the FOL translation itself) that the grid records
#   as a stack overflow.  Reducing the Acc depth removes the blow-up.  Pre-dates
#   and is independent of the projection fix.
